# oncofiles

AI-powered medical document management for cancer patients and caregivers. Connects Google Drive, Gmail, and Calendar to Claude, ChatGPT, and any MCP client.

## Quick start

```bash
uv sync --extra dev
uv run pytest
uv run ruff check
```

## Project structure

- `src/oncofiles/` — main package
- `tests/` — pytest tests
- `migrations/` — SQL schema migrations
- `data/` — local dev SQLite database (gitignored)

## Conventions

- Python 3.12+, async-first
- FastMCP 3.0+ for MCP server
- Pydantic for data models
- ruff for linting/formatting
- Filenames follow standard convention: `YYYYMMDD_PatientName_Institution_Category_DescriptionEN.ext`
  - Separators: underscores only
  - Description: English, CamelCase, max 60 chars
  - Category tokens: Labs, Report, Pathology, CT, USG, Genetics, Surgery, SurgicalReport, Prescription, Referral, Discharge, DischargeSummary, ChemoSheet, Reference, Advocate, Other, Vaccination, Dental, Preventive
  - Legacy formats (space+dash, underscore-separated) still parsed for backward compat

## Key commands

- `uv run oncofiles-mcp` — run MCP server (stdio)
- `MCP_BEARER_TOKEN=test MCP_TRANSPORT=streamable-http uv run oncofiles-mcp` — run HTTP server locally
- `uv run pytest` — run tests
- `uv run ruff check --fix` — lint and auto-fix
- `uv run ruff format` — format code

## Deployment

- **Self-hosted Mac mini** (since 2026-11-06): Coolify in a Colima Linux VM, Traefik + Let's Encrypt in front, `oncofiles.com` streamable-http at `/mcp`. Build pack Railpack, install `uv sync`, start `uv run oncofiles-mcp`. Forpsi and Railway are retired. Host/network details live in the private RUNBOOK, never in this public repo (no IPs, IDs, tokens).
- **Push to `main` deploys** via the CI `deploy` job (`.github/workflows/ci.yml`): after lint+test pass, the runner joins the tailnet as an ephemeral `tag:ci` node and POSTs to the Coolify API, then smoke-tests `/health`. Kill switch: repo variable `DEPLOY_ENABLED`. Always run `/deploy-check` after a push.
- **Env-only changes are cheap**: with an unchanged commit SHA, Coolify logs `No build configuration changed & image found … Build step skipped` and just recreates the container.
- **Never tick "Available at Buildtime"** on a new env var unless the build genuinely needs it — Railpack writes buildtime vars into a `.env` that `mise`/`aqua` read (#550).
- **DB is a local SQLite file** (aiosqlite, WAL) on the Coolify volume, path `DATABASE_PATH`. There is no cloud DB option: any non-empty `TURSO_*` env var makes startup fail (`server._assert_local_database`, #617). Data survives rebuilds; a failed deploy keeps the old container running.
- **Google**: a dedicated GCP project, named in the RUNBOOK (OAuth client, External / In production / unverified, 100-user cap accepted). `GOOGLE_INTEGRATION_ENABLED` stays `false` until the curated-folder pipeline (#562) ships.
- CI is lint + test + deploy.

## Infrastructure gotchas

- **Curated Drive folders are write-protected from legacy code (#562).** A patient root holding both `README.md` and `_index.json` is curated by its own contract (fixed folder set, sidecars, never delete). `curated_folder.mark_if_curated()` runs wherever a patient `GDriveClient` is built (`_create_patient_clients`, lifespan, `/api/gdrive-set-folder`) and sets `write_block_reason`; every write method on the client (`upload`, `update`, `create_folder`, `rename_file`, `move_file`, `trash_file`, `copy_file`, `create_shortcut`, `set_app_properties`, `grant_access`, `batch_*`) then raises `DriveWriteBlockedError`, which the retry decorator never retries. `sync`, `sync_to_gdrive`, `sync_from_gdrive` and `ensure_folder_structure` return early. Detection **fails closed** (listing error → curated). Only the contract pipeline may lift the block, via `with gdrive.contract_writes():`. Lock tests: `tests/test_curated_folder.py`. When adding a new Drive write method, call `self._guard_write("<name>")` first and add it to `WRITE_CALLS` in that test.
- **Curated-folder pipeline (#562, `src/oncofiles/curated/`)** is the only code allowed to write into a curated folder, and only inside `gdrive.contract_writes()`. Its Drive writes go through `curated/drive_ops.py`: read-back verification, **no retries**, no deletes (only its own canary is trashed). Runs are **dry runs by default**. MCP: `curated_folder_run` runs in the background (local OCR takes minutes per page, which outlasts an MCP call); poll `curated_folder_status`. OCR and classification use the **local** LM Studio model via `LOCAL_LLM_BASE_URL` / `LOCAL_LLM_MODEL` / `LOCAL_LLM_API_KEY` (runtime-only env; from the container the host is `host.lima.internal`). Never route document content to a cloud model in this path. A misread date can never rename a file: `classify.validate` requires the date to be printed in the text and not to be a README birth date. Benchmark (#565): printed Slovak excellent, old handwriting weak; dedicated OCR research is #570, split/merge is #569.
- **Curated runs vs deploys (#581).** A run executes in-process; a deploy or restart kills it. The canary `_healthcheck.tmp` is the run's write-ahead **journal** (line 1 `<run_id> journal-v1`, then one JSON line per action, written and verified *before* the action). `_actions.jsonl` is only appended at the end, so after a kill the canary is the only record. Next real run: canary older than 5 min with no journaled actions → trashed and the run continues; with actions, a legacy canary (no journal), or a fresh one → abort for a human. At startup `mark_interrupted_curated_runs()` flips stale `running` rows to `interrupted`, and the loop waits `STARTUP_GRACE_S` (5 min) so a rolling deploy's old container is gone. Never trigger a manual Coolify deploy while CI is deploying the same commit (2026-11-08: two deploys in 2 min killed a run). Each Drive client used by a run is a `dedicated_copy()` (httplib2 is not thread-safe, #577/#579). Each journaled action is followed by `{"ok": seq}` once verified (a pair only after both moves); a canary whose every action is confirmed is **recovered automatically** (actions carried into the next run's logs), any unconfirmed action still stops for a human. Shutdown calls `request_stop()`: a run finishes its current document and writes its logs. CI's deploy job waits (max 20 min) while `/health.curated_run_active` is true and then FAILS rather than kill a run (re-run the job once idle).
- **Continuous mode (default, `CURATED_CONTINUOUS=true`).** The curated loop probes each enabled patient every `CURATED_POLL_S` (120 s) with `runner.probe()` — one tree listing, sidecars read only when the tree fingerprint changed since the last idle probe, no model calls. When new work exists and the youngest inbox file is older than `CURATED_SETTLE_S` (120 s), it runs a short sequence (`trigger="auto"`, `CURATED_CHUNK_DOCS`=5 docs per run, preview reused within 24 h). Overlap: one run per patient; files landing mid-run are pending on the next probe. A sequence that moves nothing parks its pending ids until something new arrives; a failed one backs off 30 min doubling to 4 h. The nightly sweep at `CURATED_NIGHTLY_HOUR` stays as the full catch-all. LLM load: a run makes one model call at a time, so it holds 1 of LM Studio's parallel slots.
- **The curated loop never waits on a patient lock** (starvation fix, 2026-11-11): a re-OCR/re-read job holds `patient_lock(pid)` for hours, and the old loop awaited it inside `_execute`, stalling probes for every patient. Now probes always run (read-only, from `PROBE_STARTUP_DELAY_S`=15 s after boot); only the RUN waits — for `STARTUP_GRACE_S`, failure backoff, or `run_block_reason(pid)` (this patient's own run, re-OCR/re-read job or held lock; never another patient's job, never an LLM shadow job). Background runs pass `skip_if_busy=True`; a blocked run is logged at INFO once per poll and retried. Per-patient counters (`probe_stats()`: `last_probe_at`, `probes_total`, `probes_skipped`, `runs_blocked`, `last_auto_run_at`, `pending_inbox_count`) are on operator `/readiness.curated_probes` and the admin curated overview, never on public `/health`.
- **Persistent app log (#706).** `APP_LOG_DIR` (prod `/app/data/logs`, on the volume; unset locally = off) adds a daily-rotating file handler (`app_log.py`, UTC midnight, `APP_LOG_RETENTION_DAYS`=7, per-day cap `APP_LOG_MAX_MB`=50, then lines are dropped until rotation). Same lines as stderr — keep logging ids/counts/reasons only, never document values.
  Log dir is owner-only (0700), files owner-only (0600), set by chmod regardless of umask. `_setup_logging` puts one `app_log.RedactFilter` on EVERY root handler (stderr and the file): e-mail addresses, bearer/`onco_`/Google/API tokens and secret-named `key=value` pairs are masked, tracebacks included; patient UUIDs are not masked. When adding a log handler, call `attach_redaction(handler)`.
- **Curated read model (#603).** `tools/curated.index_patient` mirrors a curated folder into `documents` so the chat tools (search, `view_document`, labs, timeline) see it: one row per filed source with `file_id = "gdrive:<drive id>"` (never uploaded to the Files API; `_try_download` goes straight to Drive), sidecar body → `document_pages` (`model = curated-sidecar`, so `view_document` never re-OCRs), front matter → date/institution/summary/`structured_metadata.curated`. Drive is only read; inbox/logs/duplicates are not indexed; a file that leaves the filed folders is soft-deleted. Runs after every successful real run, once at loop start, and via the `curated_index` MCP tool; incremental by sidecar `modified`. **Curated content never goes to a cloud model:** the "without AI/metadata" queries exclude `gdrive:%` rows, and every cloud-AI function in `enhance.py`/`doc_analysis.py` calls `curated.indexer.refuse_cloud(document_id, …)` right before `_get_client()` (registry loaded at startup from `db.curated_document_ids()`). When adding a new cloud-AI function, add the same guard. `search_documents` also matches page text.
- **Drive-only documents when cloud AI is off (#777).** `files_api.files_api_refusal_reason()` is the same predicate as `enhance._get_client` (local-only job, or `CLOUD_AI_ENABLED` off / no key). When it refuses, `sync_from_gdrive` never calls the Files API and never downloads at import: the row gets `file_id = "gdrive:<drive id>"` (the curated prefix), size from the Drive listing, `structured_metadata = {"source": "drive_sync"}`, and is registered in the curated cloud refusal; inline enhance and the split/consolidate AI phases are skipped. A changed file converts its row to Drive-only and KEEPS its `document_pages` text (no `delete_ocr_pages` unless new text is written in the same step), flagged `structured_metadata.text_stale = true` until a local re-OCR replaces it. Logs in these paths (and all of `sync.py`) never print a filename — use `files_api.name_len()` next to a doc id / Drive id. Such an import counts as `new`/`updated` (+ `drive_only`), never as an error (#552). `sync_to_gdrive` skips (not errors) a row whose only copy is in the Files API, and skips post-rename re-enhance. `upload_document` with cloud off uploads to the resolved patient's own Drive folder (`_create_patient_clients(db, pid)`) and registers the row Drive-only; no Drive or a failed/blocked Drive upload → refused, nothing stored. Gmail attachments are not stored while it refuses. `_try_download` reads Drive-only rows from Drive (Google Docs exported as PDF). The curated indexer never soft-deletes a `gdrive:` row whose metadata is non-empty and not curated (`curated_index_state.foreign`). Drive-only rows are excluded from cloud enhancement even after cloud AI is turned on (same as curated). Tests: `tests/test_drive_only_sync.py`.
- **Clinical facts model (#603, migration 072).** Facts live in `clinical_records` (extended): `code` → `fact_codes` (60 seeded codes, aliases, unit conversions), `param` = original label, `occurred_at` = sample time, provenance `source_document_id` + `page_number` + `evidence` (the exact text) + `extracted_by`, `verification` ∈ machine | unverified | verified | corrected. Entities: `organizations`/`departments` (shared), `practitioners` (**patient-scoped**), `encounters` (natural key per patient/day/org/dept/kind), generic `links` (both ends checked to be the same patient). Views `fact_series_v`, `latest_fact_v` (excludes unverified), `timeline_v`. Read tools in `tools/clinical_facts.py` (overview, timeline, fact_catalog, fact_series, document_detail, encounter_detail, people_and_places) are `readOnlyHint` and resolve the patient via `_resolve_patient_id`; statistics exclude unverified values unless asked. Re-extraction (`replace_document_facts`) soft-deletes machine facts with an audit row and never touches verified/corrected ones. Nor does it re-add the extractor's version of them (#741): matched by (code, time) and the range window, by the stable fact id (a correction shares its original's `fhir_id`), and for a date-corrected fact whose id no new fact carries, by the original date of its `metadata.corrected_from` chain. Lab facts come from rule parsers (`curated/facts_rules.py`: Bory and NOÚ OKB formats), no model call; Cowork-era (non-local) sidecars yield `unverified` facts. A value printed under a date RANGE ("laboratórne 1.9.–9.9.:") is dated at the range **end** (`date_source=printed_range`, `date_precision=range`, both ends in `date_range_start`/`date_range_end`; #726 superseded the #659 midpoint, which produced a day printed nowhere). Anything comparing days across documents (fact_series dedupe, corroboration, `date_conflicts`, re-read keys, verified-fact protection) treats such a value as the whole window, never as one day. **Any change to what the parsers extract (rules, aliases in `fact_codes`, dating, corroboration) must bump `curated/indexer.INDEX_VERSION` in the same PR** — #668 shipped a parser fix without a bump, so production kept facts from two parser generations until the next full re-index surfaced 19 "unexplained" new rows (#672). Regressions compare against the production DB (infra exports per-doc code/date/verification plus a salted value hash; never raw values in a cloud-model session), not the old code against the new code.
- **Hard-data model, Phase 1 schema (#711, design `docs/architecture/hard_data_model.md`, migration 080).** Additive only, nothing moved: new tables `codings`, `provenance`, `devices`, `identifiers`, `conditions`, `cancer_stages`, `treatment_courses`, `treatment_cycles`, `medication_events`, `procedures`, `specimens`, `reports`, plus FHIR Observation columns on `clinical_records` (`result_status`, `value_comparator`, `unit_printed`/`unit_ucum`, `interpretation_code`, `effective_start`/`effective_end`/`effective_precision`, `issued_at`, `specimen_id`, `report_id`, `fhir_id`, `version_id`, `last_updated`; all NULL / 1 on existing rows) and nullable `fact_codes.plausible_low`/`plausible_high` (in `unit_canonical`, unseeded, for the generic verifier #714). Every fact table has `fhir_id` (UUID set by the writer), `version_id`, `last_updated`, `verification` (default `unverified`), soft delete and `patient_id NOT NULL`. Helpers live in `database/_hard_facts.py`: keyword-only `patient_id`, SQL-filtered, every patient-scoped reference (document, encounter, practitioner, condition, course, cycle, request, specimen) checked to be the same patient; `codings`/`identifiers.owner_type` and `provenance.target_type`/`activity`/`agent_role` are validated against Python allowlists (no CHECK, so they can grow without a table rebuild). Nothing reads these tables yet; no MCP tools until later phases. Do not backfill them in a startup migration. Tests: `tests/test_hard_facts_schema.py`.
  - **`identifiers` data minimisation:** never store a patient's national ID (rodné číslo) or insurance number (nor any MRN-like patient number) — for any owner. If matching on them is ever needed: only a salted hash, and only after a maintainer decision. `add_identifier` rejects such systems (and slash-form birth-number values) before anything else, then enforces a per-owner system allowlist (`IDENTIFIER_SYSTEMS_BY_OWNER`: ÚDZS provider code and IČO for organisations/departments, ÚDZS doctor code for practitioners, accession numbers for specimens/reports/documents). Extraction phases must not fill `identifiers` by default.
- **Data model conventions (#789): `docs/architecture/data_model_conventions.md`.** New tables and columns follow it (`id INTEGER` PK, `patient_id NOT NULL` + FK, no DEFAULT; `*_id` = FK; `*_at` ISO / `*_date`; `*_json`; a code column gets a domain with sk/en labels in `src/oncofiles/vocab.py`, an entity reference is an FK, never a text copy). `tests/test_schema_conventions.py` lints the migrated schema; its legacy allowlists may only shrink, so never add new schema to them.
- **`query_db` is scoped by SQLite itself (#738).** Each call runs on a per-call read-only connection (`file:…?mode=ro`); every patient-scoped table name is a TEMP VIEW of the caller's rows (inner view `_qdb_<nonce>_<table>`), and `set_authorizer` denies reads of `main.<patient table>` unless SQLite reports that inner view as the accessor, plus PRAGMA/ATTACH/writes/DDL/`sqlite_*`/functions off `SAFE_FUNCTIONS`. The AST check stays as the second layer. Tables without `patient_id` are scoped through their parent in `_PARENT_SCOPED` — adding such a table to the allow-list needs an entry there (lock test `test_every_patient_scoped_table_can_be_scoped`). libsql has no `set_authorizer`; on it query_db falls back to AST + CTE shadowing and logs a warning.
- **Stable fact ids + `dashboard_feed` (#726).** A fact's id is `clinical_records.fhir_id`, a UUIDv5 (`fact_identity.py`) over patient, source document, code (label when uncoded), the fact's day (a printed range keys on `start/end`, a corroborated quote on `metadata.quoted_on`), page, plus an ordinal by evidence text. `replace_document_facts` writes it at insert; re-extraction re-inserts the same id with `version_id + 1`, and the soft-deleted row keeps it as the older version, so `fhir_id` is unique among **active** rows only (migration 082). Rows with NULL `fhir_id` get the same value at read time (`ids_for_rows` mirrors the insert path). Never change `FACT_NAMESPACE` or the key composition: every id a dashboard cached would change. `dashboard_feed` (read-only, admin must pass `patient_slug`) pages by (at, id) under a ~140 kB byte budget and leaves out facts whose document is soft-deleted. Local lab abbreviations are shared `codings` rows (`urn:oncofiles:local:<lab>`, migration 081), shown as `fact_catalog.local_codes`. The legacy lab readers (`get_lab_time_series`, `get_lab_trends`, `compare_lab_panels`) read the facts model for any patient with coded lab facts and the old `lab_values` table otherwise; they and `get_lab_summary` are deprecated (removed after 2027-01-10). Tests: `tests/test_dashboard_feed.py`.
- **Local-only zones (policy 2026-11-09: background = local model only, cloud only when the user acts in Claude.ai).** `cloud_guard.local_only(job)` sets a ContextVar; `enhance._get_client()` and every Files API call (`FilesClient._guarded()`) raise `CloudForbiddenError` inside it, also in `asyncio.to_thread` workers. The curated index + fact extraction run inside it; the #619 backfill must too. New background jobs that touch documents go inside `local_only()`.
- **Local-LLM extractor rules (#767).** Both extractors (`curated/llm_extract.py` lab, `curated/llm_extract_clinical.py` clinical) call the model through ONE shared path, `curated/llm_extract_call.py` (settings, `response_format` + HTTP-400 retry, reasoning-channel fallback, `finish=length` → `truncated`, error kinds, per-page token counts); never copy that logic into an extractor again (the clinical copy missed the fallback and failed 22/22 pages). No `json_schema` `response_format` by default: with it Qwen puts the whole answer into `reasoning_content`. Sampling is `LLM_EXTRACT_SAMPLING` = `greedy` (default) | `qwen` (the Qwen3.8 model card: non-thinking T 0.7 / top_p 0.8 / top_k 20 / presence_penalty 1.5, thinking T 1.0 / top_p 0.95 / top_k 20; greedy makes Qwen3 loop to `max_tokens`, worst with thinking off); thinking off uses `LLM_EXTRACT_ANSWER_BUDGET` (4000), every call `LLM_EXTRACT_TIMEOUT_S` (300). The preview tools take per-job `thinking`/`sampling` overrides for an A/B, dry run only (a write refuses them). #770: LM Studio/MLX ignores thinking-off for Qwen3.x on pages with content. A prefilled assistant turn does not help (the Qwen3.8 chat template renders a trailing assistant message as a finished turn, never a continuation), so it was removed; do not reintroduce it (lock test `test_prefill_is_removed_everywhere`). Previews also take `timeout_s` (int, 30–900), dry run only. #770 marker: `LLM_REASONING_MARKER` (runtime env, default `false` = every request byte-identical to before; per-preview `reasoning_marker: on|off`, dry run only, passed explicitly per call, never global state) makes `llm.chat` send no `/no_think` at all and, with thinking off only, end the system message with `llm.REASONING_OFF_MARKER` (`[[reasoning:off]]`, the only place the literal lives); it works ONLY together with the LM Studio Prompt Template rule that maps it to `enable_thinking=false` (private RUNBOOK, AI zone) — with the env on, every thinking-off caller (also re-OCR with `REOCR_THINKING=off`) sends it. Fallbacks must surface as report `warnings` (`answer_from_reasoning_channel`, `truncated`, `page_errors`), never as a silent pass. Smoke-test 1 page in production before any 10-document run.
- **Session diary (`conversation_entries`, kept 2026-11-11, #721 follow-up).** `log_conversation` / `diary_add`, `search_conversations`, `get_conversation`, `get_conversation_stats`, `delete_conversation`, `restore_conversation` (`tools/conversations.py`) are a patient-scoped diary for Claude.ai / Claude Code / ChatGPT sessions, NOT deprecated with the other Oncoteam tools. Admins must pass `patient_slug`; foreign ids → `not_found`; participant from a fixed list; 20 kB/entry, 50 entries/patient/day; `document_ids` must belong to the patient; soft delete only. Diary text is local only: never to a cloud model, never to Drive (`export_manifest(include_diary=False)` in sync), never a fact source, and the audit middleware logs only `DIARY_AUDIT_SAFE_ARGS` for these tools. Any new module that reads the table fails `tests/test_session_diary.py::test_no_extractor_or_indexer_reads_the_diary`.
  Cloud AI is off by default (`CLOUD_AI_ENABLED=false`); the key alone doesn't enable it.
- **LLM-first extraction, shadow mode (#714 phase 2a).** `curated/llm_extract.py` asks the LOCAL model (one call per page of stored sidecar text, JSON schema + worked examples, `EXTRACTOR_VERSION`) for printed results with their verbatim evidence line; `curated/verifier.py` (generic, NO layout knowledge, `VERIFIER_VERSION`) decides `machine` vs `unverified` + reason codes (evidence on the page, label/unit/value digits inside the evidence, date printed and not a birth date, label → code via `fact_codes` aliases, unit conversion, plausibility). MCP `curated_llm_extract_preview(document_ids, patient_slug, dry_run=True)` is enabled by default (off-switch `LLM_EXTRACT_SHADOW_DISABLED=true`; no env needed, because it is dry-run only, explicit ids ≤ 10, local-only and refuses while another run is active), runs in the background inside `local_only()` holding one LM Studio slot (status via `curated_reocr_status`, kind `llm_shadow`), and reports per document only counts and codes (agreement on code + day + value hash, rule-only / LLM-only codes, unverified reasons, seconds). It writes NOTHING (no facts, no run row, no Drive) and does not block CI deploys. Never add per-layout parsing to the verifier; new labels are `fact_codes` aliases (data). Bump `EXTRACTOR_VERSION` on any prompt/schema change. Not stored, so no `INDEX_VERSION` bump. Plausibility ranges still live in `facts_rules.PLAUSIBLE`; they move into `fact_codes` in the Phase 1 migration.
  - Shadow report rules: a page whose answer is truncated (`finish_reason=length`), empty or unparseable is **not assessed** (`pages_not_assessed`) and is left out of the metrics on both sides, never counted as "LLM found none". The extractor uses the full `REASONING_BUDGET`, because LM Studio counts reasoning into `max_tokens` and may ignore thinking-off. Without a known DOB the report says `birth_date_guard: inactive_no_dob`; any future write path for LLM facts MUST call `verifier.require_dob_for_write()`.
  - Shadow diagnostics: each page reports `error_kind` (http_status, json_decode, schema_shape, empty, timeout, truncated, other) with the exception class, whether structured output was accepted, and the answer shape (field used, length, think tags, fences, top-level object or list, and the masked text of failed answers: digits become nines, words outside the lab vocabulary become a's). Diagnostics live only in the in-memory job report. When `content` is empty the extractor reads LM Studio's `reasoning_content`, but only if it holds exactly one complete JSON object that is valid against the schema; otherwise the page is not assessed (`reasoning_ambiguous`). Facts from that channel carry `answer_source: reasoning` and the verifier always marks them unverified with reason `llm_reasoning_channel`, never machine; any future write path must keep it that way.
  - Text-only extraction from the stored sidecar text is not an independent source (`verifier.TEXT_PATH_NEVER_UPGRADES_TRANSCRIPTION_REASONS`). On a Cowork-era sidecar, or when the matching stored fact carries `cowork_ocr`, `ocr_uncertain` or `handwritten`, the LLM fact keeps those reasons and stays unverified (`inherit_transcription_reasons` only ever adds reasons). Agreement on such pages is reported as `parser_crosscheck`, never as `agree`. Independent confirmation needs a new read of the source. The stored side is labelled: all stored facts by verification, facts without a value, facts on unassessed pages.
- **LLM-first extraction of the non-lab kinds (#726 item 4, #711 phase 2b, migration 086).** `curated/llm_extract_clinical.py` (`EXTRACTOR_VERSION` `llm-clinical-v1`, family prefix `llm-clinical` = `database._facts.LLM_CLINICAL_FAMILY`) asks the LOCAL model, one page of stored sidecar text per call, for diagnoses, biomarker/genomic results, treatment courses, cycles (incl. postponement + printed reason), medication doses, procedures (surgery/biopsy/imaging/radiotherapy/endoscopy), CT lesion sizes and planned dates, each with a verbatim evidence passage. The worked examples are built from `EXAMPLES` (invented, 2027+) and a test requires every example item to verify as machine. `curated/verifier_clinical.py` (generic, no layout rules) gives `machine` only when the evidence is on the page, every returned token (drug, gene, variant, result, unit, route, label…) is inside it, numbers (dose, size) occur whole outside the label/unit/dates, every date is printed on the page AND inside the evidence and is not a birth date; biomarkers must map to a `genetic_variant`/`biomarker` `fact_codes` alias.
